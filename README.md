# Galata | گالاتا

گالاتا یک نرم‌افزار اندرویدی **مدیریت و حسابداری آفلاین کسب‌وکار** است. اطلاعات اصلی در دیتابیس داخلی دستگاه نگهداری می‌شوند و برای فروش، مشتری، فاکتور، تسویه و یادآورها به سرور نیاز نیست.

## نسخه

- Version Name: `1.0.0`
- Version Code: `10`
- Package: `com.asteam.galata`
- Min SDK: 24
- Target / Compile SDK: 35
- زبان: Kotlin + Android Views
- دیتابیس: SQLite داخلی با Migration افزایشی

## قابلیت‌ها

- ثبت‌نام یک‌باره مالک و ورود محلی
- ارتقای خودکار رمز قدیمی SHA-256 به PBKDF2 + Salt بعد از ورود موفق
- Drawer راست‌به‌چپ با پروفایل و عکس کاربر
- مشتری‌ها: افزودن، جستجو، ویرایش، حذف/بایگانی و صورت‌حساب
- کالا و خدمات: قیمت خرید/فروش، موجودی اختیاری، CRUD و جستجو
- فروش: انتخاب مشتری و کالا، تعداد، سبد، پیش‌نمایش، دریافتی لحظه‌ای و فروش نسیه
- فاکتور: Snapshot نام/قیمت، آرشیو، جزئیات، اشتراک و لغو بدون حذف سابقه
- Ledger مشتری: بدهی، پرداخت، اصلاح، لغو و بازپرداخت با مانده بعد از هر رویداد
- تسویه کامل و پرداخت جزئی
- تفکیک فروش روزانه از دریافتی روزانه
- هزینه‌ها و گزارش سود ناخالص/خالص
- تقویم ماهانه و هفتگی شمسی
- یادداشت روی روزهای تقویم
- یادآور چک، قسط، قرار و عمومی با مبلغ و ساعت
- اعلان محلی و زمان‌بندی مجدد بعد از روشن‌شدن گوشی
- Backup / Restore دیتابیس با بررسی سلامت فایل
- بررسی اختیاری نسخه جدید از `version.json`
- نمایش همه مبالغ به تومان با ارقام فارسی و جداکننده سه‌رقمی `٫`

## مدل مالی

گالاتا «فروش» را با «دریافتی» یکی نمی‌گیرد. اگر امروز فاکتور ۱٫۰۰۰٫۰۰۰ تومان ثبت شود و مشتری چیزی پرداخت نکند، فروش امروز ۱٫۰۰۰٫۰۰۰ و دریافتی امروز صفر است. پرداخت روز بعد فقط دریافتی روز بعد را افزایش می‌دهد و فروش قبلی را تغییر نمی‌دهد.

مانده مشتری از Ledger محاسبه می‌شود و هیچ دستور مستقیمی برای صفرکردن عدد بدهی وجود ندارد. حتی «تسویه کامل» یک Payment واقعی برابر مانده ثبت می‌کند.

## ساخت و امضا

Workflow فایل‌های Debug و Release را Build می‌کند. کلید انتشار نباید داخل این ریپوی عمومی قرار بگیرد. برای Release قابل‌انتشار، Secrets زیر باید در GitHub تعریف شوند:

- `GALATA_KEYSTORE_B64`
- `GALATA_KEYSTORE_PASSWORD`
- `GALATA_KEY_ALIAS`
- `GALATA_KEY_PASSWORD`

بدون این Secrets، Release برای QA به شکل unsigned تولید می‌شود و فایل `release-signature.txt` این وضعیت را مشخص می‌کند.

> مهم: APKهای نسخه‌های 0.x که با Debug Key موقت CI ساخته شده‌اند ممکن است با کلید Publish دائمی v1 قابل Upgrade مستقیم نباشند. از v1 به بعد باید همیشه یک Keystore Publish ثابت استفاده شود.

## ساختار مهم سورس

- `GalataDb.kt`: دیتابیس، Migration، فروش، Ledger و گزارش
- `JalaliDate.kt`: موتور تاریخ شمسی
- `ReminderSystem.kt`: اعلان و Alarm محلی
- `BackupManager.kt`: Backup/Restore
- `MainActivity.kt`: Drawer، Navigation و Back Stack
- `ui/`: صفحه‌های مستقل برنامه
